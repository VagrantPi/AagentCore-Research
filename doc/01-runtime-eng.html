ELI5 · Senior Engineers · Bedrock AgentCore

Runtime = Lambda 的 function→version→alias，再多一層有狀態的 session

每個 session = 一台專屬 microVM。開發者的 surface 只有兩個 endpoint。

← 00 總覽 01 Runtime目錄 02 Memory →

1資源模型

Runtime          一個 agent / tool，有自己的 execution role
├── Version        不可變 · 最多 1,000 · 改 image/協定/網路都出新版本
├── Endpoint       最多 10 · DEFAULT 自動指最新 · prod/staging 手動釘版本
└── Session       runtimeSessionId（≥33 字元）→ 一台 microVM

你要寫的只有 0.0.0.0:8080 上的 POST /invocations + GET /ping，ARM64 container。換協定只是換 port 和路徑（MCP 8000 /mcp、A2A 9000 /、AG-UI 8080 SSE）。

2閒置 15 分鐘、上限 8 小時 — 消失的是 VM 不是 session

✗session ID 永不失效。VM 被回收後，同一個 ID 再呼叫 → 全新空 VM，記憶體狀態沒了。
✗沒帶 session header（X-Amzn-Bedrock-AgentCore-Runtime-Session-Id）→ 每個請求都可能落到新 VM，每次都冷啟動。
✓閒置計時器每次呼叫重設；maxLifetime 從 VM 建立起算，不重設。閒置越短越省（記憶體閒置仍計費）但冷啟動越頻繁。

!/ping 決定 session 生死 — 兩個相反的坑

阻塞 handler 會把 /ping 一起卡住

單執行緒程式中只要有阻塞操作，/ping 就回不了 → 15 分鐘後 session 被當成閒置砍掉，背景工作一起死。阻塞的東西必須丟到其他執行緒或改 async。

把 time_of_last_update 每次都設成 now → 永遠不進閒置

平台以為狀態一直在變，session 會一路跑到 8 小時上限，配額被耗光。自寫 /ping 時這個欄位要回報「上次實際變動時間」，不是「現在」。

附帶：session 建立/銷毀途中送請求會拿到 409 RetryableConflictException。AWS SDK 會自動重試，但 MCP 協定回 HTTP 200、錯誤包在 JSON-RPC body 裡，不會自動重試——要自己接。

3Runtime ≠ 使用者

✗AgentCore 只驗 session ID，不驗這個 session 屬於誰。後端若直接轉送前端傳來的 session ID，A 拿到 B 的 ID 就能進 B 的 VM。user↔session 對應、每使用者 session 數上限，都要自己維護。
✗VM 內任何程式都能透過 MMDS 拿到 execution role 憑證，而 agent 會執行自己生成的程式碼 → 權限不得大於「能呼叫這個 agent 的人」。
✓Gateway 放前面並鎖死只接受 Gateway（繞過 Policy / Guardrails / interceptor）；限制 agent 碰 localhost（平台服務在那裡，= SSRF 進 shell）。

4版本切換不影響進行中的 session

✗VM 跑的是建立當下的程式碼。發新版本後舊 session 繼續跑舊碼，最長 8 小時。這段新舊並存期的 API 相容性要自己設計。
✗UpdateAgentRuntime 是 full PUT：改一個設定也必須帶齊所有必填欄位。
✓用不可變 Version + 具名 Endpoint 做 canary / 藍綠；回滾就是把 Endpoint 指向舊版。

5V2 = SnapStart：init 階段的狀態會被複製

冷啟動穩定，代價是 init 做的事凍結在快照裡——每個還原的實例拿到一模一樣的值。

✗ 亂數 / UUID / token全部實例同值（random seed 也一樣）→ 改用 os.urandom()
✗ OpenSSL 取亂數還原後不重新取 seed（官方已知限制）→ 向 OS 要
✗ 記時間 / time.monotonic()時間凍結在快照那刻、monotonic 不前進 → handler 裡重取
✗ hostname / PID 當 ID全部 localhost / PID 1 → 每請求自己生成
✗ 快取憑證 / 工具清單過期或凍結在快照時 → 執行期間取

可以放 init：import、靜態設定、暖機（client 已解析的設定會保留，連線不會）。代價：建版要幾分鐘、120 秒內 /ping 必須健康、環境變數額度砍半、CFN / CDK 設不了 platformVersion。

6狀態放哪

VM 記憶體／本機磁碟VM 停就沒 · 暫存
Session storage（預覽，1 GB）跨停止恢復，但 14 天未用清空、升版本也清空
EFS / S3 Files（需 VPC）永久 · 可跨 session 與 agent 共用
EBS（僅 Instances）到 session 刪除為止 · 長任務 checkpoint
AgentCore Memory永久 · 對話歷史與使用者偏好

用 Session storage 當 coding agent 工作區 → 每次部署新版本，使用者的專案目錄被清空。要留就放 EFS。
