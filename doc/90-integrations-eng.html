框架整合 = 不綁框架

任何框架（或不用框架）都能接上 AgentCore。關鍵選擇只有一個：要為框架寫專用 adapter，還是走 MCP。

1三種接法，通用性遞減

透過 Gateway 走 MCP任何支援 MCP client 的框架都能用 Gateway 上的工具、Memory connector、Web Search。最通用。
直接呼叫 SDKIdentity 的 @requires_access_token、Code Interpreter 的 client —— 任何 Python 框架都能用。
框架專用 adapterStrands 的 memory session manager、LangGraph 的 checkpointer、Payments 的 plugin。整合最深、程式碼最少，但綁框架。

判斷原則：能走 MCP 就走 MCP，框架差異會降到最低，以後換框架也容易。只有需要「深入框架生命週期」的功能（checkpoint、模型呼叫前的 hook、自動攔截 402）才用專用 adapter。

!評估是依 span 的 scope name 認框架

自己改寫或包裝 instrumentation，可能導致無法評估

評估服務靠span 的 scope name 判斷這是哪個框架的資料。包裝或改寫 instrumentation 就可能讓它認不出來。

Instrumentation 套件有最低版本要求

LangGraph OTel 需≥ 0.55.0、Claude Agent SDK 需 ≥ 0.1.3、Strands TS 需 ≥ 1.5.0。版本不夠，評估服務會讀不懂 span。

!兩個會靜默漏資料的坑

Strands Memory：batch_size > 1 時一定要 close()（或用 with）

沒有收尾的話，最後一批還沒送出的訊息會遺失 —— 不會報錯，資料就是少一截。

LangGraph：thread_id 和 actor_id 是對應到 Memory 的 session 與 actor 的必填欄位

AgentCoreMemorySaver 管短期記憶與 checkpoint，AgentCoreMemoryStore 管長期記憶。兩個 ID 要跟 Runtime 的 session 設計一致，填錯就是記憶錯亂而不是報錯。

!Claude Agent SDK 沒有模型呼叫 span

就是 Claude Code 背後的框架，內建檔案操作、shell、MCP，擅長 coding 類任務。部署到 Runtime 可以，工具走 Gateway 拿治理能力也可以。

只有 AGENT 和 TOOL 兩種 span，沒有獨立的模型呼叫 span

模型名稱和 token 用量記在 AGENT span 上 → 依賴「模型呼叫 span」的分析或評估方式要另外調整。Harness 的 export 功能官方標示「即將推出」，要評估請用 openinference-instrumentation-claude-agent-sdk（≥ 0.1.3）。

!選框架前先確認缺口

✗Payments 的自動 402 處理只有 Strands 和 LangGraph 有 —— 其他框架要自己攔截 402 並呼叫 ProcessPayment。
✗CrewAI 不在評估支援的框架清單裡（Observability 有提到）→ 只能走通用 instrumentation，評估要自己接。
✓新專案想用最多功能、寫最少程式碼 → 先用 Harness，要自己掌控迴圈再 export 成 Strands。要 graph／狀態機 → LangGraph。團隊已熟悉的框架就直接沿用，不必為了 AgentCore 換框架。

→導入前的六個檢查

  1. 工具、Memory、Web Search 能走 MCP 就走 MCP嗎？換框架時要改多少
  2. Instrumentation 的版本門檻满足了嗎（LangGraph 0.55.0／Claude Agent SDK 0.1.3／Strands TS 1.5.0）
  3. 有沒有自己包裝 instrumentation？那會讓評估認不出框架
  4. Strands Memory 的 close() 有做嗎；LangGraph 的 thread_id／actor_id 對得上 session 設計嗎
  5. 選的框架需要自動 402 嗎？不是 Strands／LangGraph 就要自己接
  6. 要 Claude Agent SDK 的話，缺模型呼叫 span 的評估怎麼補
